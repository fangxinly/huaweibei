# V8C：观测来源检查

本版本保存一个局部研究假设的反例，未实现或训练完整的 V8 真实数据模型，也未启动 GPU pilot。

## 已核验反例

三个完整输入进入四步联合 Euler 流；速度场把文本坐标传入音频接收状态。合成标签仅由原始文本生成，音频和视觉为独立随机输入。使用独立生成的训练和验证样本，各4096条，种子128、0、1、2、3。

在流结束后，只观察音频状态的回归头，验证 MSE 为0.0095–0.0103；它实际上读取的是已经传入的文本证据。删除流结束后的文本和视觉状态，对该预测的影响为0；在流开始前删除文本输入并在每一步保持不可用状态为零，该头的验证 MSE 升至0.9510–1.0232。真正按音频输入路径训练的预测头验证 MSE 为0.9386–1.0103。

后流音频头对原始文本输入的导数约0.989–0.993，直接揭示信息来源。由此，流内接收块的预测可靠性不能作为原始模态贡献的证据。这是植入线性场的反例，不是在已训练的 MOSI 网络上观测到的故障。

## 对后续结构的要求

1. 完整主路径仍从完整 T/A/V 状态开始进入流；不在输入前命名共享、补充、噪声分支。
2. 若使用单/双/完整七个任务视图测量原始模态贡献，应以输入可用性定义七条观测路径。不可用状态在整个输运过程中保持约定的干预，不能只在流结束后遮挡接收块。
3. 所有比较配置使用相同观测路径、预测头与辅助损失；用训练集学习对应干预，用验证集检查视图误差、不确定性和原始输入敏感性。
4. 接收流位置与原始模态证据分别记录。部分状态可能由其他流传入，不能将接收位置直接解释为信息来源。
5. 多视图任务保护仍只是一阶预测约束。未训练、未验证的视图不能直接用于正式控制；非线性有限步漂移、约束秩、控制是否启用须另行检查。
6. 七条路径的容量和计算开销要有匹配对照。该反例不证明共享/补充/冗余语义已分解，也不证明新颖性、真实性能优势或 SOTA。

检查使用本地 NumPy，未使用真实数据、测试集或 GPU。旧五种子实验及 V7 队列源码、数据、参数与选择规则保持冻结。本版本先修订观测假设；真实模型、校准和100轮验证尚未执行。
