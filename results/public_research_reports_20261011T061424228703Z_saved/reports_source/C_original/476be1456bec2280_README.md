## 实验推动的修改

### 1. 共同运动不能直接等同于共同语义

彼此独立的输入也能通过一个加法场驱动相同的输出方向。这提供了反例：仅凭运动重叠，无法断言已经得到共享情感、补充信息和噪声的信息论分解。

因此，候选只把重叠称为“多个模态共同驱动的运动”。是否与情感有关，要另由任务预测和控制实验检验。

### 2. 保留接收流身份

V7A/B 将三个接收流的响应当作同一 D 维坐标空间内的列，可能把“文本驱动文本、音频驱动音频、视觉驱动视觉”误识别为三者共有。

已用恒等速度场确认这个问题：旧读法给出支持编码 7，新联合空间读法给出 1、2、4，即三个独有方向。新响应向量由三流输出连接而成，维度为 3D；完整模态仍先进入联合场，然后才测量关系。

### 3. 对齐没有启用时如实报告

V7B 的两个真实训练样本中，四步平均未判定比例约 0.969–1，对齐方向数量为零。半对齐的整数预算也可能把唯一候选方向的预算取整为零。

V7C 初始真实样本同样未检出可靠共有方向。软响应算子仍提供循环反馈；仅可靠共有方向可以接受压缩。后续必须记录共同方向数量和控制范数，不能把速度场或反馈带来的收益归于一个未启用的压缩分支。

V7C 中 rho 为可靠共有方向的连续权重，不再宣称是语义信息的占比，也不是硬选取方向数的比例。比较 rho=0.5/0.75 时，必须加入减小整体控制力度的对照；初版中 rho 与 alpha 只通过乘积影响压缩力度，二者不可作为独立创新。

## V7C 结构

1. 文本、音频、视觉完整状态进入联合连续速度场，先预测完整三流的速度。
2. 对各模态施加小扰动，测量完整三流输出的局部响应。它们在同一个联合空间中比较，保留接收流身份。
3. 根据三个响应算子产生三者共同、两两共同、各自独有以及未判定的动力学方向候选。非交换或不清楚的方向允许弃权。
4. 先按速度场演化，再在可靠共同方向上施加任务保护的压缩。独有方向和未判定方向没有强制压缩。
5. 第一阶段的响应算子平均后反馈第二阶段；第二阶段接续第一阶段终态。none、instant、memory 均使用同一容量的速度场与四个更新步骤。
6. 完整终态与第一阶段终态参与情感预测。训练损失在所有新对照中相同。

令 A 为可靠共同方向上的半正定控制算子，z 为完整状态，g 为当前情感预测对状态的梯度，控制为：

`c = -alpha*A*z + alpha*(g^T*A*z)/(g^T*A*g)*A*g`

它满足 `g^T*c = 0`（一阶预测保护），且 `z^T*c <= 0`。控制仍在 A 的作用范围内。这里不主张三模态控制之和为零；该性质只适用于旧版本的成对拉近算子。

这将“把共同表征一律拉近”改为一个可检验的假设：保留影响当前情感预测的共同运动，压缩当前预测不敏感的共同运动。预测不敏感不等于真实噪声；预测器可能尚未学好，也可能过度依赖文本。当前标量任务之外的信息可能改变。

## 已有检查及其边界

- V7B 线性任务：普通对齐预测变化 0.0245646；保护后变化约 4.44e-16。非线性有限步长变化约 0.0001201，不能保证精确不变。
- V7C 合成例子：已知共有情感的预测和独有补充项保留，共有干扰范数由 2.9540 降至 2.8802。这些角色仅在植入真值的合成例子中已知。
- 真实样本检查：预训练权重核验 198 个张量，三模态与速度场均有有限非零梯度；优化器确实更新，padding 与样本独立性检查通过。压缩分支在这些样本上仍未启用。
- 对保护逐 token 情感坐标不变的断言曾失败；修正为该任务实际观察的池化预测不变。不能将标量预测保护扩大解释为保留所有情感细节。
- 大矩阵只保留控制与反馈需要的部分，四步记录保留紧凑统计，减少 batch128 的显存风险。仍需在空闲 GPU 上验证实际峰值。

`run_validation.py` 已准备，真实 GPU 检查和正式 pilot 尚未启动。`research_pipeline.py` 已开始等待旧队列，CUDA 阶段会拒绝在旧五种子队列未 COMPLETE 时抢占 GPU，并等待其他GPU进程退出。它不终止其他进程。

先用 stage=check 验证 train batch32 和 dev batch128；检查过后按同一 seed128、同一100epoch依次进行：

| 配置 | feedback | rho | guard | 要验证的机制 |
|---|---|---:|---|---|
| coupled | none | 0 | on | 联合速度场基线 |
| instant | instant | 0 | on | 当前响应反馈 |
| memory | memory | 0 | on | 接续循环的累计反馈 |
| guarded | memory | 0.5 | on | 任务保护的共有运动压缩 |
| unguarded | memory | 0.5 | off | 无保护压缩对照 |

这些是验证集探索，不进行测试集评估，也不当作五种子结论。每次使用新目录，记录源码、数据、backbone、协议与 checkpoint 哈希。监管脚本会先执行前三个对照；仅当 memory 的训练或验证日志曾检出可靠共同方向时执行 guarded/unguarded，否则记录跳过原因，先修订关系估计，避免两个压缩对照在该机制未启用时重复训练。

如果训练后共同方向/控制范数长期为零，应先修改关系估计假设。若只有反馈改善预测，结论仅归于反馈。若无保护与有保护都无效，撤回压缩有益的假设。若音频/视觉利用仍偏弱，先审查输入和可学习信号，不继续堆模块。

候选通过机制诊断和验证集对照后，再冻结方法、按官方划分运行五个种子，最终一次性报告测试集均值与样本标准差、同种子的成对差异。新颖性与 SOTA 优势目前均未证明。本阶段只使用项目已有资料，没有打开网页。
