# 官方实现、V6 与离线原型的口径纠正

## 用户指出的问题

用户指出 MAE 0.9–1.0+ 的实验没有沿用 CaReFlow 官方代码和完整训练流程。这一点成立：最早 V1–V4 和后来冻结特征的小型流原型，都不能算官方 CaReFlow 复现。后续把小原型的失败扩展成“原无交换基线不可靠”，忽略了已经完成的官方复现与 V6 端到端实验，是研究方向判断上的错误。

## 已有结果分别来自什么实现

这些 TEST 与 DEV 数字不能直接计算性能差值。表格用来澄清实验身份。

官方复现锁定 commit：`5c9f9c7a0bb3f1202ebb3258052da2b99710c565`。训练导入作者模型源码；评价流程调整为验证集选模、结束后测试一次，避免作者脚本每轮查看测试集。五种子报告已完成；早期 README 的“单种子”状态是历史记录。

V6 沿用了作者骨干和训练框架，但替换了流结构，并修改输入处理，因此仍是自定义改进版本，不能称“未修改的官方 CaReFlow”。官方 sampled interpolation velocity regression 与 V6 自定义共识目标/重建损失需要逐项对照。

## 为什么离线原型不能代表原方法

冻结池化特征取消了端到端编码器适配和序列结构；12 维瓶颈、速度场、辅助目标、优化器也同时发生变化。其训练误差很低、开发误差较高，只能说明这个小原型存在泛化问题。它不能证明官方流、V6 或原始任务目标失败。

没有同条件消融，不能把差成绩定量地全部归因某一个代码差异。“没有沿用官方完整训练流程”是已确认的事实；各差异贡献多少仍未识别。
