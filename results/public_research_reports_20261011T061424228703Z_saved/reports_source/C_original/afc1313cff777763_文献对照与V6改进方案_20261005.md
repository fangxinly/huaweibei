# 从流研究回到 V6：目标、条件信息与循环的区分

本轮按用户要求回到 V6，并查阅下列论文正文及原作者项目资料。以下是研究依据与待检验方案，不是新训练结果。

## 直接相关的研究

| 原始研究 | 可参考的内容 | 对 V6 的约束 |
|---|---|---|
| [Flow Matching，ICLR 2023](https://arxiv.org/html/2210.02747v2) | 用指定条件概率路径的速度回归训练向量场 | 要说明端点、路径与目标速度；仅使用 Euler 更新不能自动获得分布输运结论 |
| [Rectified Flow，ICLR 2023](https://arxiv.org/html/2209.03003v1) | 端点线性插值、端点差速度目标、重新配对的 rectification | 轨迹更直与情感误差下降是不同问题，reflow 也不是重复运行同一个前向模块 |
| [Conditional Flow Matching，TMLR 2024](https://arxiv.org/pdf/2302.00482) | 一般源分布和端点耦合；OT 配对用于改善输运路径 | 可以使用实际模态表示作为源；几何上距离小的跨样本配对未必保留任务标签 |
| [CaReFlow，2026](https://arxiv.org/html/2602.19140v1) | A/V 向文本分布映射；同样本与跨样本使用不同松弛；反向速度匹配约束 | 其 cyclic 指反向训练目标；不是推理时重复两轮前向。标签距离在训练松弛中使用，不能解释成已识别共享比例 |
| [Improving the Training of Rectified Flows，NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/hash/7343a5c976f8399880b695267f1f9e9f-Abstract-Conference.html) | 少步生成中研究训练时间采样与损失设计 | 可启发检查两步积分的训练覆盖；图像 LPIPS 与生成结果不能直接作为 MOSI 的损失或收益依据 |
| [AV-Link，ICCV 2025](https://arxiv.org/html/2412.15191v2) | 在冻结音视频生成器内部，通过融合块交换中间状态并注回两支 | 可借鉴流内条件交互的位置；其生成任务、预训练资源与时间对齐机制不能直接替代当前完整 T/A/V 情感任务 |

综述入口：[Flow Matching Guide and Code](https://arxiv.org/abs/2412.06264)。本轮阅读了该入口摘要；不把摘要阅读写成完整综述正文精读。

## 对当前 V6 源码的实际核对

核对文件：`../own_flow_v6/flow_model.py`、`encoder_adapter.py`、`run_ours.py`，以及 CaReFlow 本地 PDF 正文。旧五种子结果用于描述已有基线，不用旧 test 分数选择新系数。

1. V6 每个模态速度场接受当前本模态状态、时间和 context。single 的 context 始终为零；关系组进入最终 role residual 头，但没有在速度场中造成跨模态条件反馈。因此 single 的前向速度并不直接读取其他模态的样本状态。这是结构事实，不等于整个 single 预测器没有跨模态融合。
2. V6 的 flow matching 目标端点是关系槽形成的 `consensus_target`，含手定的 0.25 共识移动。它不是直接采样的文本目标分布，也没有证明对应情感相关共享信息；关系余弦相似度不能代替任务关系真值。
3. V6 cycle 的每次前向 pass 都从原 source 重新开始，保留 context。它不是从第一轮 terminal 沿同一 ODE 继续积分，也不是 Rectified Flow 的 reflow 重新训练配对过程。
4. V6 的 `cycle_reconstruction` 是把 terminal 经两步独立 backward field 恢复到 detached source 的重建 MSE；CaReFlow 反向项则对反向插值路径上的速度进行端点差回归。两者都试图保留输入信息，但训练目标不相同。
5. V6 已实现 `mid` 分支，一次前向内在第一步后读关系、反馈给第二步；原 runner 未开放该选项。它能用于隔离中段条件反馈与额外前向 pass。其几何关系仍只能称候选。
6. V6 每坐标速度被限定在 ±0.5，两步总时间为 1。任何实际端点位移的绝对值都不会超过 0.5；若共识目标超出这个范围，存在容量约束。应先测保存的训练目标超限比例，不能从这个界断言实际目标已经不可达。

在标准确定性线性桥中，给定端点有：

`z_t = (1-t) z_0 + t z_1`，`u_t = z_1-z_0`。

关键实验选择是 z_1 代表什么。把它改成所有模态的均值，会把“接近”作为目标，却不保证保留互补或冲突信息。这里不先强制音视频整体变成文本，也不据本文献声称无损或风险单调下降。

## 下一组预写的 V6 对照

先保留 V6 的完整序列、mask、归一化、编码器和预测头。采用新 seed91801、从预训练初始化开始；旧 128/0/1/2/3 权重与测试全部保留，不重跑。设置四个新学生构成 2×2：

| 一次前向的条件反馈 | 原 flow matching + backward reconstruction | 关闭这两个辅助项 |
|---|---|---|
| 无，single | fresh single 原目标对照 | single 任务目标对照 |
| 有，mid | mid 原目标对照 | mid 任务目标对照 |

“任务目标对照”仍保留原 V6 的相同单模态与方差辅助项，仅关闭 flow_matching_weight 与 cycle_weight，不修改关系 residual 头。这个设计分别检查共识/反向辅助项组合与中段反馈；不拆分两项辅助损失的单独因果。四模型共用初始化来源和完整构造，反馈模块有效使用不同，不声称有效容量完全相同。

每组 100 轮、train32/drop_last、dev128，原 AdamW 分组/lr1e-5/warmup10%，官方 1281 TRAIN/229 dev；开发 pilot 不访问或推理 test。原 loader 若反序列化含 test 的 pickle 容器，要准确记录容器读取事实，仅索引 TRAIN/dev，不能宣称未读容器字节。

先审核来源/预训练/梯度/真实更新/mask与batch不变性，再启动一次新训练。第 100 轮之前不更换上述配置；dev 按原 batch MSE 选 checkpoint。新基线用于匹配新代码/资源，不能以老检查点的不同节点训练作为唯一因果对照。先完成这一 seed 的完整曲线与机制记录再决定后续，不预报五种子收益。

拟定三卡分配：A 串行 fresh single 原目标→single 任务目标；B mid 原目标；C mid 任务目标。尚未部署、检查或训练。后续必须 fresh UUID/完整 ps/compute/磁盘通过，唯一所有权与完成保存后接续，禁止重复启动。
