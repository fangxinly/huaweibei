# CaReFlow实现审计与后续实验

## 1. 当前实验

使用作者仓库commit `5c9f9c7a0bb3f1202ebb3258052da2b99710c565`，MOSI默认种子128、100轮训练。首轮已完成，最佳检查点第72轮，测试含零MAE0.6450、去零Acc2为87.18%。源码、协议、结果、检查点均已核对，指标已从保存预测独立复算。正式指标以 `careflow_seed128/results.json` 为准。

输入是词级对齐的文本、74维语音与47维视觉特征。文本由DeBERTa-v3-base编码并微调；音视频由卷积投影和各自的三层Transformer编码；随后各模态平均池化成100维向量。

## 2. 官方模型具体做了什么

| 环节 | 实际计算 | 代码位置 |
| --- | --- | --- |
| 前向映射 | 语音→文本分布、视觉→文本分布，各有一个带时间嵌入的速度MLP | `official/model_reflow_new.py:223` |
| 求解 | 两次Euler更新，时间0和0.5，步长0.5 | `official/model_reflow_new.py:127` |
| 融合 | 拼接文本、映射后的语音、映射后的视觉，输入MLP | `official/model_reflow_new.py:226` |
| 训练配对 | 同一样本配对，加随机跨样本配对，跨样本候选数为batch×4，过滤自身配对 | `official/model_reflow_new.py:158` |
| 宽松对齐 | 同样本margin=0；跨样本margin=eps+标签差平方 | `official/model_reflow_new.py:165` |
| 反向流 | 学习从转移表示重建原模态，作为训练辅助目标 | `official/model_reflow_new.py:183` |
| 任务目标 | 情感分数MSE+0.2×前向流损失+0.1×反向流损失 | `official/train_reflow_new.py:275` |

**该实现没有显式的共享／两两共有／独有／噪声分支。** 循环重建会鼓励保留源模态信息，但没有指定保留的信息必须是与情感有关的特有信息。

流在推理阶段的速度网络输入只有当前单模态状态和时间，不读取同一样本的另两个模态。因此，虽然它学习了跨模态分布映射，但没有在每个流步判断“三个模态此刻共享了什么”。文本向量直接进入融合层，没有经过第三条可学习流。

**这里的循环是训练目标中的前后向映射，不是关系读取结果反馈给下一轮前向流的推理循环。** 反向速度网络在推理时不运行。这与用户提出的循环反馈有明确区别。[作者仓库](https://github.com/TmacMai/CaReFlow)、[论文](https://arxiv.org/html/2602.19140v1)。

## 3. 需要记录的代码细节

### 3.1 梯度路径与论文表述有差异

前向流辅助训练中，目标文本向量被detach，但源音视频向量没有detach（`model_reflow_new.py:162–163`）。因此，前向流损失可以更新音视频编码器。这与论文中“前向流损失不更新单模态网络”的描述并不完全一致。

Euler求解时，速度网络读取的是detach后的当前状态，但状态本身仍通过残差更新进入下一步。因此任务损失能训练速度MLP和源编码器；跨步状态对速度的链式梯度则被截断。不能把这段实现笼统解释成“整条流完全detach”。

本轮按公开代码运行。若复现明显不足，源码差异可以成为下一项单因素审计，不能在本轮中途修补。

### 3.2 循环训练使用的不是完整Euler终点

反向辅助损失接收的是 `source.detach()+v_pred`，其中速度取自同样本随机插值点（`model_reflow_new.py:178`）。它不是前面两步Euler求解得到的预测终点。因而：

- 反向辅助损失小，不足以证明推理终点可以准确重建源模态。
- 若后续验证重建性质，需要单独对真正的推理终点积分反向速度场并测量误差。

### 3.3 归一化与评估口径

音视频分别使用整个batch的单个min/max做归一化；训练batch32、验证与测试batch128。预测可能受到同一批其他样本的影响。后续比较必须保持batch划分一致。

默认没有启用文本attention mask，且池化包含填充位置。本轮保留作者设置。启用mask是一项独立的实现变体，应重新训练并另列结果。

验证选择使用“每批MSE的均值”，最后一批101个样本与前一批128个样本权重相同；这不同于按样本平均MSE。本轮沿用作者选择规则。

作者评估函数同时输出含零／去零标签MAE。我们的结果也记录两者，以及含零／去零Acc2。与论文比较时要明确口径，不能只从多个值中取更好看的那个。

## 4. 已准备的验证集诊断

`diagnose_validation.py` 只在正式训练完成后读取选定检查点，使用验证集。模型保持eval模式，不更新参数，也不再次评价测试集。

1. 核对检查点、源码、数据、预训练模型与训练入口哈希。
2. 通过hook保存三个源表示和真正进入融合层的三个表示。
3. 复算原始验证预测，与正式实验保存的预测逐项核对。
4. 用验证集均值替换文本、映射后的语音／视觉表示，记录MAE变化。
5. 对各模态及音视频组合做20次固定种子的样本置乱，记录变化均值和标准差。
6. 测量映射前后的模态间余弦、位移范数和样本间方差。

置乱发生在表示提取之后，所以保留正式验证中的min-max统计与batch边界。均值替换与置乱可能产生分布外表示；它们反映当前融合头对表示的依赖，**不是重新训练后的消融结果，也不是因果效应**。余弦接近也不能证明情感共享信息已经被找出。

输出为 `validation_diagnosis.json` 和 `validation_features.npz`。原始验证表示将保留，方便后续可复核的分析。

该诊断已执行完成。音视频联合置乱使验证MAE仅增加约0.0002，去零Acc2不变；文本置乱使验证MAE增加约1.1585。当前融合头明显依赖文本。音视频源表示在流前就具有较低样本间变化，不能把问题仅归因于流，也不能直接把此轮指标改善解释成多模态融合成功。

## 5. 下一轮需要保持的比较条件

先确认官方模型的单种子结果和验证诊断，再确定是否补做多种子与强编码器下的基础融合对照。此前V4的冻结BERT特征、5／20维音视频输入与本轮不同，不能作为新增流结构的直接对照。

最小比较组：

| 组别 | 修改内容 | 回答的问题 |
| --- | --- | --- |
| A | 当前官方模型 | 官方实现能达到什么水平？ |
| B | 保持输入和编码器，去掉分布流与两项辅助损失，重新训练融合模型 | 收益来自流还是强编码器？ |
| C | 官方流中增加关系读取，暂时关闭反馈，重新训练 | 读取共有与特有信息是否有收益？ |
| D | C中启用关系对速度场的反馈，重新训练 | 反馈是否提供额外收益？ |
| E | 与D相同的循环次数，关系反馈置常量或置乱 | 收益是否来自有效关系而非额外计算？ |

各组使用相同种子、样本、归一化、训练预算和验证选择规则；同时报告参数与时间。模块选择只使用训练／验证集。冻结骨干的小规模筛查可以筛实现错误，但不能替代最终在相同微调条件下的比较。

## 6. 用户方向的实现边界

目标是从完整的流状态中读取三模态共有、两两共有与模态独有信息，再以读取结果影响下一步速度场；不先把编码器输出硬切成三种坐标子空间。

后续结构应满足：

- 每个模态先进入完整表示的流；关系读取发生在流的中间状态。
- 读取结果区分几何相似、情感一致与预测价值，避免把相似直接命名为“有用共享”。
- 独有信息不能一概当噪声删除；需要验证其在其他模态之外的预测价值。
- 对共享信息“拉近”需要控制重复计数；把冗余信息“推远”并不能自动删除无用信息。
- 第一轮关系摘要作为第二轮速度网络条件，且单独比较第一轮和第二轮预测。
- 共有／两两共有／独有层级已有相关工作，创新需要落在流内关系识别、训练约束与反馈机制，并通过对照验证。

本文件是代码审计与实验方案。官方首轮和验证诊断已完成；无流融合与文本单模态对照已通过梯度与参数更新检查，正式进度见 `control_baselines/status.json`。流内信息读取与反馈的新结构尚未训练，也尚未被证明有效。
