# 第六轮：先恢复音视频有效信号，再检验流与循环

## 已完成结果

三组均完成seed128、100轮，指标与检查点核验通过：无流融合测试MAE **0.6143**、single **0.6323**、cycle **0.6243**。两个流版本均没有超过同条件无流对照；仅单种子，不能证明稳定优劣。

等长度音视频联合置乱的验证MAE增加仅约0.0013／0.0019／0.0018，音视频辅助情感头及固定线性探针仍较弱。完整记录见[结果汇总](结果汇总.md)。后续独立音视频学习率诊断另置于 `../av_learning_audit`。

## 动机

第五轮已完成：single测试MAE为0.6218、cycle为0.6411；文本单模态为0.6411。single虽有单种子改善，音视频联合置乱在验证集只使MAE增加约0.0015。

第五轮single选定检查点的验证诊断发现：音频、视觉辅助线性头MAE约1.418，接近训练标签均值常量的1.419；文本头为0.596。验证输入约72.3%为padding，而之前沿用作者的无mask编码和全序列均值。上述现象是修复输入处理的动机，不证明padding是唯一原因，也不意味着音视频本身没有情感信息。

## 本轮固定改动

1. 仅使用训练集、词片对齐后有效内容token，拟合每个音视频通道的均值和标准差；三组实验共用该规则。小于1e-6标准差的通道置零。删除随batch变化的全局min-max归一化。
2. DeBERTa使用原input mask。音视频Transformer保留原层数、权重布局和各层参数，用显式key padding mask屏蔽CLS、SEP和padding；位置编码从mask生成。
3. 音视频输入先屏蔽无效位置，防止卷积邻域接收padding值；各层输出、流状态、速度积分、流匹配／重建损失和最终池化均使用内容mask。
4. 流内关系读取、反馈与全部目标权重沿用V5。新轮不是将共有／独有分支放在流前；仍是完整状态进入流后读取关系。

## 三组对照

| 版本 | 主任务＋相同单模态／方差约束 | 流和七类关系头 | 条件反馈 | 完整流次数 |
| --- | --- | --- | --- | --- |
| plain | 有 | 无 | 无 | 0 |
| single | 有 | 有 | 无 | 1 |
| cycle | 有 | 有 | 有 | 2 |

所有版本先构造相同模块，使编码器、融合头、辅助头的初始参数配对。plain中流相关模块未使用，single中反馈模块未使用，因此不声称有效容量相同。plain与旧无流对照相比，还增加了相同信息保持辅助目标；本轮三组之间用于比较流／循环整体机制，不能把跨轮改进单独归因于mask或归一化。归一化和mask的单项消融尚未运行。

## 协议

MOSI作者数据1281／229／685；DeBERTa-v3-base；seed128；100轮；batch32；作者AdamW分组、1e-5学习率和10%warmup；验证batch128平均MSE选择检查点；训练完成后测试一次。全部参数从原预训练初始化重新训练，不接续V5检查点。相同seed不保证各版本训练过程中的随机采样完全相同。

代码／数据／骨干／统计量／检查点哈希记录在protocol与selection中。真实数据检查必须验证198个预训练张量、关键梯度、warmup之后参数更新，以及预测对batch组成和padding值扰动的不变性。检查分数为未训练模型的分数。

## 状态与文件

三组训练与验证诊断已完成。训练顺序single→cycle→plain，运行过程中不改源码、不使用测试集调参。原始完成包和新增诊断包分别核验，最佳检查点均已保存本地。

- `encoder_adapter.py`：固定训练统计、显式mask和批次前向。
- `flow_model.py`：V5关系结构的mask修正版；保留原CPU结构检查。
- `run_ours.py`：训练、真实数据检查和验证选模。
- `diagnose_ours.py`：仅验证集的第一／最终预测、辅助头和模态置乱诊断。
- `run_pipeline.py`：一次性三组训练队列，错误写入FAILED并停止。

即使分数提升，仍要确认音视频辅助头优于常量、置乱有可重复影响、关系读取未塌缩，再讨论语义分解、循环收益和多种子验证。
