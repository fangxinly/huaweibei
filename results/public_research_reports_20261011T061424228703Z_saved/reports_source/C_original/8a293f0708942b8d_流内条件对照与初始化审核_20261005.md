# 流内条件对照与初始化审核

## 研究问题和新实现

参考此前已保存的流文献，先检验条件信息进入后续速度场是否有开发集效用。新模型保留完整序列、DeBERTa 微调、音频/视觉编码器以及 V6 的 mask、TRAIN 统计归一化、末端融合和几何辅助目标。它是自定义端到端模型，不是未修改的官方 CaReFlow。

三组新学生使用 seed91811。none 的速度场条件为零，state 使用第一 Euler 步后的本模态/另外两模态状态读出及两者差，task 使用同阶段三个任务预测及预测差，经 tanh(pred/3) 后重复到相同输入维度。条件输入 detach；投影网络可训练。第二 Euler 步及原有相应 FM/反向训练目标使用条件，因此比较的是完整训练程序，不是只改变推理的一项纯因果实验。

none 仍保留末端融合、role head 和几何 FM 目标；不能叫整个模型完全无跨模态交互。task 头是普通监督任务预测，不是独立的共享/互补/干扰真值，没有外部教师或风险安全保证。混合后的接收块也不能当原始来源。

三组均构造相同参数，计算两种条件投影，保留相同辅助监督：原 .05 单模态系数一半监督原来源预测，一半监督第一阶段预测。状态条件提供完整向量、任务条件提供少数标量；参数相同不表示有效信息容量相同。与旧 V6single 相比辅助监督有变化，因此采用新 none 学生作为控制，不把旧 TEST 成绩作为新对照。

固定100轮、train32/drop_last、每轮40次更新、AdamW原分组lr1e-5/warmup10%、dev128按平均batchMSE选模；100轮批次索引显式预生成保存。TRAIN1281/dev229；原pickle容器含TEST，但新入口只请求TRAIN/dev，不索引或转换TEST。选定新 checkpoint 最后保存默认dev及预定冻结条件关闭dev，区分独立训练控制与同权重消融。已有dev为开发探索，单seed及节点绑定限制保留。

## 初始化检查中的意外结果

最初三GPU端到端检查均通过198预训练张量、真实训练损失梯度、两个warmup优化器步骤、padding/批次组成不变。流模块初始化SHA及全部100轮批次SHA一致，但整模型state SHA不同，因此没有据此开始100轮正式训练。

进一步仅构造新模型、记录352个初始状态张量SHA，不做forward/update。350个完全一致；仅 dberta.transa.embed_positions._float_tensor 和 transv对应张量不同。作者 position_embedding.py 用 torch.FloatTensor(1) 创建未初始化占位缓冲区，forward只在type_as中使用其dtype，不使用数值。父进程PYTHONHASHSEED固定后这两个缓冲区仍不同，不能把差异解释为hashseed造成学习参数不同。

新v2入口仅将这两个占位缓冲区置零，并在正式run开始时要求整模型初始化SHA等于已通过检查的SHA。旧v1、原官方代码、旧实验、失败日志全部保留。v2端到端检查和训练的实际状态以新runtime proof为准；本文不把源码准备当训练完成。

## 尚需的判断

本实验只能回答开发探索中普通状态/任务预测条件是否值得继续，不能证明语义因素被识别、共享方向正确、稳定改善或SOTA。实际完成后独立审核100轮选模、官方229标签、保存预测指标、源码/权重SHA；有支持再准备可靠性复核。所有旧84大权重、旧测试及已完成原型不重跑。
